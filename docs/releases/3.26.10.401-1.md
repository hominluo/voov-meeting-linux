# VooV Meeting 3.26.10.401 (1)

First **native** release of VooV Meeting for Linux — no Wine anywhere.

The client is Tencent's official Linux build of Tencent Meeting 3.26.10.401
(the China product; Tencent ships VooV for Linux not at all) re-identified as
VooV with a set of binary patches. It runs natively, connects to VooV's
servers, and **logs in with a real VooV account** end-to-end. It is packaged
with native desktop integration and VooV branding.

This release replaces the previous Wine-based `3.43.0.510` releases, which
have been removed.

## Source

- Application: Tencent's official
  `TencentMeeting_0300000000_3.26.10.401_x86_64_default.publish.officialwebsite.deb`
  (197,268,516 bytes,
  MD5 `72e0e0023e1d1e6d4123fba28821aea1`,
  SHA-256 `70f37b029209c0ef91be9813eebf6650c6cb9a00f7c718490158773e2fe6acaf`).
- Patches: `scripts/patch-linux-build.py`, described in
  [docs/REVERSE-ENGINEERING.md](../REVERSE-ENGINEERING.md). The set covers the
  settings hook (`+0x420`/`+0x4c8`), the endpoint string table, the channel
  id, the product and deployment identity, the WeChat QR-login URLs, the
  branding strings and the login page logo.

## What works

- Native startup on X11 (and through XWayland on Wayland sessions) — the
  client ships its own Qt runtime, so no Wine and no system Qt is needed.
- The patched client establishes and holds its signaling connection to
  `conn.voovmeeting.com` instead of the China `conn.wemeet.tencent.com`
  (verified with an `LD_PRELOAD` getaddrinfo/connect tracer).
- **VooV login, end-to-end**: the in-app WeChat QR flow completes after phone
  confirmation and the client lands on the home screen; the phone-number form
  (all 213 regions) uses the same VooV backend.
- VooV branding: window title, in-app product name and the login page logo
  are VooV, and the package installs Tencent's icon art under the name
  "VooV Meeting" (`StartupWMClass=wemeetapp`).
- State goes to the standard XDG directories; the `/opt` tree stays
  read-only.

## Install

Direct packages are attached below: `.deb`, `.rpm`, AppImage, a Flatpak
bundle and a `.snap`. Package-manager channels:

```bash
# Arch Linux (AUR push pending maintainer key)
yay -S voov-meeting-bin

# Debian / Ubuntu
echo "deb [trusted=yes] https://github.com/hominluo/voov-meeting-linux/releases/latest/download/ ./" \
  | sudo tee /etc/apt/sources.list.d/voov-meeting.list
sudo apt update && sudo apt install voov-meeting

# Nix / NixOS
nix profile install github:hominluo/voov-meeting-linux

# Flatpak bundle (Flathub listing pending)
flatpak install --user ./VooV-Meeting-3.26.10.401-1-x86_64.flatpak

# Snap (store upload pending)
sudo snap install --classic --dangerous ./voov-meeting_3.26.10.401_amd64.snap
```

AUR, Fedora (COPR), openSUSE (OBS) and the Snap Store are prepared in the
repository and will go live once their accounts are set up; see the README
for the current status table and the exact commands.

## Notes

- Update/telemetry endpoints still point at Tencent Meeting's China servers
  (`report.meeting.tencent.com`, `updatecdn.meeting.qq.com`) — cosmetic.
- On Wayland the launcher forces XWayland (`QT_QPA_PLATFORM=xcb`); the
  client's X11 helper otherwise segfaults on startup.
- The Flatpak disables the embedded browser's Chromium sandbox (it cannot
  run inside the Flatpak sandbox).
- The AppImage needs FUSE 2, or run it with `--appimage-extract-and-run`.
- The Flatpak needs `org.freedesktop.Platform//25.08`; Flatpak downloads it
  from Flathub on first install.
- The bundled Tencent binaries are proprietary; the patched libraries and
  resources are redistributed in patched form. Only the scripts and packaging
  are MIT licensed.
